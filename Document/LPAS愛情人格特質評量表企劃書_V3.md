## 第一章　專案概述

### 1.1 LPAS 在做什麼

LPAS（Love Personality Assessment System，愛情人格特質評量表）是一份線上問卷，但它的真正用途不是給填寫者看的——填寫者得到的是一份關於自己的人格描述，**而系統同時在背景生成一份「給 AI 看的角色設定書」**，讓小說家可以拿著這份設定，請 AI 寫出真正像這個人的故事。

換句話說：**每一位真實填過問卷的人，都可能變成一篇短篇小說裡的女主角**。

### 1.2 LPAS 在系統裡的位置

LPAS 是 LoveIsABitMessy 系統五個工具中的第一個，負責**產出角色的人格地基**。完整流程：

```
LPAS（這份問卷）→ 角色卡編輯器 → LoveLine 聊天驗證 → 每日日記 → 小說產生器
```

LPAS 給的不是最終的角色，而是骨架。後面四個工具負責補血肉、驗證、養活、組裝。

### 1.3 設計核心問題

**「怎麼讓 AI 真的理解一個『人』，理解到它寫出來的角色會自己推動劇情？」**

LPAS 對這個問題的回答是：把愛情拆成三個階段——曖昧、熱戀、失戀——分別測量同一個人在三個階段的真實行為傾向，因為**一個人在曖昧期、熱戀期、失戀期的樣子可能完全不同**，這種跨階段的差異，才是「人」的真實樣子。

## 第二章　四個行為軸

LPAS V3 採用 **4 條真正獨立的行為軸**，從 V1 / V2 多次試錯後確認下來：

### 2.1 軸向定義

| 軸 | 正向（+1） | 反向（−1） | 測量重點 |
|---|---|---|---|
| **initiative**（主動 vs 被動） | **A** 主動 | **P** 被動 | 是否主動製造接觸、主動表達、主動結束 |
| **pace**（快速 vs 緩慢） | **F** Fast | **S** Slow | 感情投入與消化的速度節奏 |
| **expression**（外放 vs 內斂） | **O** Outward | **I** Inward | 情緒與感受的表達是否外顯 |
| **possess**（佔有 vs 自由） | **H** Hold | **L** Let-go | 是否要求獨佔、是否能放手 |

### 2.2 四軸的命名與內部代碼

| 給受測者看（口語） | 內部代碼 |
|---|---|
| 主動／被動 | initiative：A／P |
| 快／慢 | pace：F／S |
| 外放／內斂 | expression：O／I |
| 佔有／自由 | possess：H／L |

每個階段（曖昧／熱戀／失戀）會根據四軸的傾向組合出一個 4 字母代碼，例如 `A-F-O-H`（主動－快速－外放－佔有），對應到 16 個天候型之一。

### 2.3 與 V2 的差別（為什麼放棄 V2 的三軸）

V2 採用的是「黏度／愛之語／浪漫度」三個帶有解釋性的軸，但實作後發現這三個軸彼此**仍有相關性**（例如黏度高的人，往往也偏向言語表達），這違反了測量學的獨立性原則。

V3 退回更基礎、行為導向的 4 個軸，每一條軸都是可被觀察的單一行為向度，不夾帶解釋。題目寫法也改為「每題只測一條軸」的硬規定。

## 第三章　16 個天候型

### 3.1 為什麼是天候

天候是人人都有切身經驗的意象，海嘯、煙火、漩渦、陣雨——每個名字一說出來就有畫面、有溫度、有節奏。比起「主動外放型」這種乾的描述，「海嘯型」一個詞就能把這個人是怎麼愛人的全部概念帶出來。

16 個天候型對應 4 軸的 16 種組合（2×2×2×2=16）。

### 3.4 描述語氣統一原則

所有描述都遵循「心理諮商師對個案說明」的語氣：**清楚、有同理、不過度評價**。所有描述（short、三階段、roleplay、traps、growth_keyword）一律**不使用軸分類詞**（主動／被動／快速／緩慢／外放／內斂／佔有／自由），改用該型名稱的意象（海嘯、煙火、漩渦⋯⋯）作為描述核心。

## 第四章　性象限（4 類型）

### 4.1 為什麼獨立出來

性議題對成年小說（甚至所有成年角色）都是關鍵維度，但**性的人格與一般情感人格是兩個不同向度**，硬塞進四軸會稀釋四軸的解釋力。所以 V3 把性獨立成一個額外段落，使用兩個軸測量、產生 4 個象限類型。

### 4.2 兩軸定義

| 軸 | 高（+1） | 低（−1） |
|---|---|---|
| **sex_emotion**（情感依附） | 高依附（要愛才有性） | 低依附（性與愛可分） |
| **sex_openness**（開放度） | 開放（接受多元形式） | 專一（堅持一對一） |

### 4.3 4 個象限

| 象限 | 名稱 | Tagline |
|---|---|---|
| 高依附 × 專一 | **深情專一型** | 「沒有愛，我給不出身體」 |
| 高依附 × 開放 | **鍾情博愛型** | 「我能愛很多人，但都是真心」 |
| 低依附 × 專一 | **靈肉分離型** | 「性是性，愛是愛，但我只玩一個」 |
| 低依附 × 開放 | **遊戲人間型** | 「性不需要承諾，愛也不需要獨佔」 |

每個象限在 `web/js/lpas_v3_types.js` 的 `SEX_QUADRANTS_V3` 中也有完整的 desc / roleplay / traps / pairing / growth_keyword 結構。

### 4.4 跳過規則

性象限段落獨立呈現，進入前會顯示提醒：「下一段包含性議題，可選擇整段跳過或單題跳過」。

- 若答題數 ≥ 6 題：依答題題目計算兩軸平均，分到四象限之一，顯示性標示卡
- 若跳過題數 ≥ 5 題：不顯示性標示卡，改顯示「您跳過了較多題目，本次不進行性象限分析」
- 結果頁的性標示卡有 **眼睛圖示** 👁，預設開啟，點擊可隱藏內容（適合對外分享截圖）

## 第五章　題庫設計

### 5.1 總題數與結構

| 段落 | 題數 | 結構 |
|---|---:|---|
| 曖昧期 | 16 | 4 軸 × 4 題（2 正向 + 2 反向） |
| 熱戀期 | 16 | 4 軸 × 4 題 |
| 失戀期 | 16 | 4 軸 × 4 題 |
| 性象限（選填） | 8 | 2 軸 × 4 題 |
| **總計** | **56** | |

> 註：V3 將每軸題數從 V1 / V2 的 5 題壓縮為 4 題（2 正向 + 2 反向），是為了消除 acquiescence bias（同意傾向偏誤），同時讓總題數更友善（從 60 降至 56）。

### 5.2 雙題庫設計

每一題在系統裡同時維護兩個版本：

| 題庫 | 風格 | 適合對象 |
|---|---|---|
| `LPAS_QUESTIONS_V3_PART1` | **正式版**：書面、中性、無情感詞綴 | 較年長受測者、正式場景 |
| `LPAS_QUESTIONS_V3_PART2` | **生活版**：沉浸式情境題、具體場景、可代入畫面 | 年輕受測者、輕鬆場景 |

兩份題庫共用同一套 `id`、`axis`、`direction`、`period`，**direction（正反向）必須一致**，避免計分混亂。

#### 範例對照

| id | PART1（正式版） | PART2（生活版） |
|---|---|---|
| Q01 | 你會主動製造與他偶遇的機會。 | （沉浸式情境改寫） |
| Q03 | 你習慣等對方先聯絡你。 | （沉浸式情境改寫） |
| Q11 | 你喜歡他，會藏得很好。 | （沉浸式情境改寫） |

### 5.3 取題邏輯：雙題庫隨機抽題

```javascript
function pickQuestion(id) {
    const pool = [
        LPAS_QUESTIONS_V3_PART1.find(q => q.id === id),
        LPAS_QUESTIONS_V3_PART2.find(q => q.id === id)
    ];
    return pool[Math.floor(Math.random() * pool.length)];
}
```

**每個題目每次填答時，從 PART1 / PART2 隨機抽一份呈現**。同一受測者重複測試時，連同一題的「文字」都會變化，避免熟悉感影響作答誠實度。

### 5.4 階段內隨機洗牌

進入每個階段時，該階段 16 題執行 Fisher-Yates 洗牌，避免題目順序產生序列偏誤。

### 5.5 題目寫作原則

V3 將寫作原則做得非常硬：

1. **每題只測一條軸**（直白、單義、不曖昧）
2. **同軸不同期的題目絕不可互換**（每題鎖死該期專屬情境）
3. **每軸 4 題 = 2 正向 + 2 反向**
4. **每題 ≤ 28 字、每子句 ≤ 14 字**
5. **兩版同 id 對應相同測量目標 + 相同 direction**
6. **避免多重否定句**（會讓受測者無法直覺回答）
7. **盡量不用否定句**（同上）
8. **使用中文文法**：時間 + 主詞 +（否定）+（副詞/方式）+（把+受詞）+ 動詞
9. **繁體中文**

詳細寫作規範見 `.agent/skills/project-spec/角色設計規範.md`。

## 第六章　評分系統

### 6.1 基本計分

七點量表：1 分（最同意）～ 7 分（最不同意）。

**反向題翻轉**：`direction === -1` 的題目，得分翻轉為 `8 - raw`。翻轉後，所有題目分數方向統一。

### 6.2 軸代碼判定

```javascript
for each phase in [曖昧期, 熱戀期, 失戀期]:
    for each axis in [initiative, pace, expression, possess]:
        avg = 該階段該軸 4 題的平均分（反向題已翻轉）

        if avg >= 4.0:
            label = 軸正向字母（A / F / O / H）
        else:
            label = 軸反向字母（P / S / I / L）

    四字母組合 → 查 TYPE_MAPPING_V3 → 16 型之一
```

### 6.3 性象限計分

```javascript
if 已答題數 >= 6:
    sex_emotion = 已答情感依附題的平均
    sex_openness = 已答開放度題的平均
    根據兩軸落入四象限之一
else if 跳過題數 >= 5:
    不顯示性象限卡
```

## 第七章　結果頁規格

### 7.1 三階段架構

結果頁分三聯顯示——例如「海嘯－岩漿－深海」——同一個人在三個感情階段可能是完全不同的型號。這正是 LPAS 的核心觀察：**人在不同階段，會展現完全不同的樣貌**。

### 7.2 結果頁元素清單

1. **三聯型號名**（大字主標）：例 海嘯 — 岩漿 — 深海
2. **三階段雷達圖**：4 軸 × 3 期疊圖，當前焦點期間高亮，其他淡化
   - 曖昧期：紫 `hsla(266, 56%, 64%, 1.00)`
   - 熱戀期：粉橘（V0.9.4.0 起調整）
   - 失戀期：藍（V0.9.4.0 起調整）
3. **Chapter 1：曖昧期** — 型號名 + 該期描述（150 字）+ 過場動畫
4. **Chapter 2：熱戀期** — 同上
5. **Chapter 3：失戀期** — 同上
6. **性象限卡**（含 👁 切換顯示）
7. **成長關鍵字**（一句溫柔的提醒）
8. **配對提示**（最契合／最互補／最危險）
9. **行動按鈕**：下載角色卡 JSON、下載測驗紀錄、複製 Markdown、截圖分享

## 第十章　使用範例

### 10.1 一份完整的測驗結果

某位 27 歲的女性受測者，答完 56 題之後得到的結果：

- **三聯型號**：海嘯 — 岩漿 — 深海
- **意義**：她在曖昧期是海嘯——一旦心動就以最強烈、最公開的方式撲過去；在熱戀期變成岩漿——慢、深、持續流動、覆蓋一切；在失戀期沉成深海——平靜的表面下，永遠記得每一場風暴

這就是 V1 / V2 都做不到的事：**單一類型描述不出這種人，但三聯型號可以**。

### 10.2 該如何被 AI 使用

這位受測者的角色卡 + Markdown 摘要可以直接餵給 Ollama，prompt 大致如下：

```
你現在要扮演一位 27 歲的女性角色。
她的人格在三個感情階段呈現不同樣貌：
- 曖昧期：海嘯型——主動、快速、外放、佔有。她會直接、激烈地表達，不繞圈子。
- 熱戀期：岩漿型——主動、緩慢、外放、佔有。她不急著表達，但每一天都在前進。
- 失戀期：深海型——被動、緩慢、內斂、佔有。她藏起傷痛，內心記得每一場風暴。
- 性象限：深情專一型。

請以這位角色的口吻、節奏、用詞，回應以下情境：
[使用者輸入]
```

LoveLine 與 novel_generator 就是用這套機制讓 AI「成為」這個角色。
