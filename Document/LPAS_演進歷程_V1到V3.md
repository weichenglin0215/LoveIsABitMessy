## 為什麼要寫這份文件

任何系統的當前樣貌都是一連串設計決策的結果。對 LPAS 來說，**三個月內歷經三個大版本**——每一次都不是「微調」，而是把核心架構整個拆掉重來。理解這條演進路徑，比直接讀 V3 規格更能讓人明白：

- 為什麼軸是現在這 4 條，不是別的
- 為什麼類型是 16 個天候名，不是 8 個或 16 個傳統人格名
- 為什麼性議題獨立成段
- 為什麼題庫有雙版本
- 為什麼有「公開卡 vs AI 卡」這個概念（即使 V3 最後又整合回一份）

如果未來再次重大改版，這份文件會是「不要再走的彎路」的紀錄。

## 第一段：V1（2026-04 ～ 2026-06 初）

### V1 的設計初衷

最早的設計來自一份小說創作工作坊的需求：**怎麼讓 AI 真實地扮演具有複雜情感深度的女性角色，而不只是輸出一個扁平的個性描述？**

V1 的核心洞察當時就已經成形：**一個人在曖昧、熱戀、失戀三個階段的行為可能完全不同，而這些差異才是讓角色有血有肉的關鍵。**

這個洞察一路延續到 V3，從未改變。

### V1 的四個軸

| 軸 | 正向 | 反向 |
|---|---|---|
| 靠近與表達 | **A** 主動直接 | **P** 內斂迂迴 |
| 受傷消化 | **O** 對外釋放 | **I** 對內吸收 |
| 告別疏遠 | **C** 乾淨切斷 | **L** 模糊拖延 |
| 關係節奏 | **F** 燃燒型 | **S** 滲透型 |

### V1 的 16 型

V1 的 16 型命名比較傳統（太陽、月亮、潮水、燈塔、薔薇、霧、深海、流星、颱風、冰川、溫泉、玻璃、候鳥、礁石、煙火、守護），帶有詩意但缺乏天候意象那種「一說就有畫面」的強度。

### V1 的限制——為什麼會走向 V2

實作幾週後，幾個問題浮現：

1. **類型過多**：16 型 × 三期獨立分型 = 4096 種三聯命名，受測者得到的型號太難記憶、太難分享
2. **命名抽象**：「告別疏遠」這種軸名給填寫者看不直觀
3. **沒有測量性議題**：對成年小說來說是個關鍵缺口
4. **單一描述**：同一份角色描述既要溫柔給人看、又要結構化給 AI 看，兩個目的互相妥協

於是有了 V2 的整個架構翻新。

## 第二段：V2（2026-06-05，V0.9.0.0）

### V2 想解決的問題

V2 最大的賭注是**「收斂」**：把軸從 4 條收成 3 條、把類型從 16 個收成 8 個，希望換來更高的辨識度與記憶度。

### V2 的三個軸

V2 用了帶有解釋性的軸名，希望讓填寫者更直觀：

| 內部代碼 | 給填寫者看 | 兩極 |
|---|---|---|
| 依附邊界 | **黏度** | Fuse（融合焦慮）↔ Free（獨立迴避） |
| 表達通道 | **愛之語** | Ver（言語）↔ Act（行動） |
| 浪漫框架 | **浪漫度** | Rom（浪漫理想）↔ Pra（務實條件） |

### V2 的 8 型

| 代碼 | 名稱 | Slogan |
|---|---|---|
| Fuse·Ver·Rom | **公主** | 「你是我的全世界——而我需要你天天告訴我」 |
| Fuse·Ver·Pra | **女王** | 「我愛你，但你要照我的方式回」 |
| Fuse·Act·Pra | **守護者** | 「你的人生我來扛，但別問我累不累」 |
| Fuse·Act·Rom | **寶貝** | 「我用全身撲過去，靠近你就是我的事」 |
| Free·Ver·Rom | **浪子** | 「我說的每一句都是真的——直到我說的下一句」 |
| Free·Ver·Pra | **貓系** | 「我先看清楚，再決定要不要喜歡你」 |
| Free·Act·Rom | **獨行俠** | 「我不在，但需要時你會發現我留了東西」 |
| Free·Act·Pra | **總裁** | 「我給的不是承諾，是可執行的計畫」 |

### V2 的三大創新（雖然 V2 已被取代，這三個創新都延續到 V3）

#### 創新一：性象限獨立

V2 第一次承認**「性的人格」與「一般情感人格」是兩個不同向度**。把性獨立成一個額外段落、使用兩個軸測量、產生 4 個象限：

- 深情專一型（高依附 × 專一）
- 深情多元型（高依附 × 開放）—— V3 改名為「鍾情博愛型」
- 探索人性型（低依附 × 專一）—— V3 改名為「靈肉分離型」
- 自由遊戲型（低依附 × 開放）—— V3 改名為「遊戲人間型」

並設計了「可整段或單題跳過」的機制，與結果頁的「眼睛圖示」隱藏切換。**這整套設計被 V3 完整繼承**。

#### 創新二：雙題庫設計

V2 引入了 PART1（正式版）+ PART2（生活版）的雙題庫，每題從兩版隨機抽一份呈現。這解決了「重複測試會記得題目」的問題。**這個設計也被 V3 完整繼承**。

#### 創新三：公開卡 vs AI 卡

V2 第一次把「給人看的角色描述」與「給 AI 看的角色規格書」徹底分開：

- **公開卡**：Slogan + 三階段樣貌（150 字）+ 戀愛超能力 + 戀愛陷阱 + 配對提示 + 成長關鍵字。**約 700-800 字**，含畫面感、金句、戳心點，給填寫者看
- **AI 卡**：軸向參數 + 核心心理（意識上想要 / 真正需要 / 相信的謊言 / 害怕的真相 / 原型傷口）+ 行為驅動樹 + 觸發反應對照表 + 對話模式 + 三階段樣貌 + 內外落差 + 衝突生成器 + 寫作禁忌 + 場景模板。**約 1500-2500 字**，純結構化規格書

雖然 V3 最後把這兩份合併回一份結構化角色卡（加上 Markdown 摘要），但**「給人看 vs 給 AI 看的需求不同」這個觀念深深影響了 V3 的設計**。

### V2 的其他重要設計

- **三期共用 8 型池**（不像 V1 三期各自分型）：8³ = 512 種三聯命名，比 V1 的 4096 種好記憶
- **三聯命名**：例如「公主－女王－浪子」，這個命名方式被 V3 繼承（變成「海嘯－岩漿－深海」）
- **經典劇本庫**：從 512 種三聯中挑出 20 個有故事感的命名為「彩蛋」（如「童話覺醒劇本」「花心翻車劇本」）
- **配對矩陣（8×8）**：每組配對含戲劇張力、化學反應、衝突核心、結局傾向
- **結果頁 9 元素**：三聯名 + 雷達圖 + 三章節 + 性標示卡 + 經典劇本彩蛋 + 配對提示 + 分享按鈕

### V2 的限制——為什麼僅 4 天就走向 V3

V2 在 2026-06-05 發布，2026-06-08 就啟動了 V3 改版。為什麼這麼快？

1. **三個軸仍然不獨立**：實作後發現黏度高的人通常也偏向言語表達、浪漫理想的人通常也黏度高——這違反了測量學的獨立性原則
2. **8 型不夠用**：8 型在三期共用池子的情況下確實好記憶，但每一型內部的個體差異被壓平了。實際生成角色時，作者常覺得「這個角色就是公主，但她跟另一個公主完全不同」
3. **抽象軸名仍然抽象**：「黏度」「愛之語」「浪漫度」聽起來直觀，但解釋給填寫者反而比 V1 的「主動／被動」更繞
4. **角色化命名（公主、女王、浪子⋯⋯）有刻板印象包袱**：受測者容易自我帶入「我希望我是哪一型」而非「我實際上是哪一型」

### V2 已實作的部分（歷史紀錄）

依當時的進度紀錄，V2 在被 V3 取代之前已完成：

- ✅ 8 型公開卡（Phase 1.2）
- ✅ 8 型 AI 卡（Phase 1.3）
- ✅ 19 個經典劇本（Phase 1.4）
- ✅ 配對矩陣 MVP 20 組（Phase 1.5）
- ✅ PART1 / PART2 各 55 題（Phase 2.1 / 2.2）
- ✅ 評分邏輯（Phase 3.1）
- ✅ 結果頁 6 元素渲染（Phase 4）
- ✅ 答題流程 + 過場 + 性題跳過（Phase 5）
- ✅ 煙霧測試頁
- ✅ DB schema 遷移 SQL

V2 的程式碼以 `web/js/lpas_v2_*.js` 命名，目前仍保留在專案中，與 V1 / V3 並存但不再被首頁指向。

## 第三段：V3（2026-06-09 ～ 現在，V0.9.2.0 起完整體）

### V3 的設計賭注

V3 是一次「回到 V1 的骨架（4 軸 + 16 型 + 三期各自分型），但帶著 V2 學到的所有經驗」的重新出發。

關鍵決策：

- **回到 4 軸**：但這次選擇真正獨立、行為導向、不帶解釋的軸名
- **回到 16 型**：但這次用天候意象命名，每個名字一說就有畫面、有溫度、有節奏
- **保留 V2 的性象限設計**：直接繼承，幾乎沒改
- **保留 V2 的雙題庫**：直接繼承
- **題數從 5 題/軸 降到 4 題/軸**：減少 acquiescence bias，也讓總題數友善
- **整合公開卡與 AI 卡**：合成一份結構化角色卡 + 一份 Markdown 摘要，後者可直接餵 prompt

### V3 的 4 條獨立軸

| 軸 | 正向 | 反向 |
|---|---|---|
| initiative（主動／被動） | A | P |
| pace（快／慢） | F | S |
| expression（外放／內斂） | O | I |
| possess（佔有／自由） | H | L |

這 4 條軸都是**單一可被觀察的行為向度**，不夾帶解釋。題目寫作改為「每題只測一條軸」的硬規定。

## 設計演進的幾個關鍵教訓

從這三個版本的演進中，可以歸納出幾個對未來改版有用的教訓：

### 教訓一：軸的獨立性不能用直覺判斷，要看實作後的資料

V1 設計時以為四軸獨立，實作後發現有相關。V2 改為三軸但仍相關。V3 真正獨立——是因為這次軸的選擇刻意避開「解釋層」（不再用「告別疏遠」這種帶有判斷的詞），改用最底層的行為向度。

### 教訓二：類型命名決定填寫者的心理錨點

V2 的「公主、女王」雖然好記，但讓填寫者帶入「我希望是哪一型」的偏誤。V3 的「海嘯、煙火、漩渦」是中性意象，沒有「哪一個比較好」的暗示。

### 教訓三：類型數的甜蜜點是「能被記住，但能涵蓋差異」

8 型太少（壓平差異）、4096 種三聯太多（記不住）。V3 用「16 型基底 + 三聯命名顯示」找到平衡——你記得「我是海嘯型」這一個基底就夠了，三聯只是錦上添花。

### 教訓四：給人看 vs 給 AI 看的需求真的不同，但實作上可以整合

V2 把公開卡與 AI 卡分成兩個檔案，V3 把它們合進同一份結構化角色卡，但保留 Markdown 摘要欄位給 AI 使用。**觀念分離，實作整合**——後者降低維護成本。

### 教訓五：性議題獨立測量是對的決定

V1 完全跳過性議題，V2 引入獨立的兩軸四象限，V3 完整繼承。實作後驗證：性議題如果硬塞進一般情感人格的軸裡，會稀釋整套架構的解釋力。獨立出來，並提供「可跳過」的選擇，是兼顧深度與舒適度的方式。

### 教訓六：每題只測一條軸是硬規定

V1 / V2 的題目經常一題同時測到兩條軸（例如「我會主動傳訊息給他」同時測「主動」與「外放」），導致計分時某些題目對多個軸都有貢獻，數學上很亂。V3 把這條訂為硬規定，從題目產出端就避免問題。

## 一個重要的延伸：性議題的命名演進

性象限的 4 個名字在 V2 → V3 改了 3 個，這個改名過程本身就是一個有趣的觀察：

| 象限定義 | V2 名稱 | V3 名稱 | 改名原因 |
|---|---|---|---|
| 高依附 × 專一 | 深情專一型 | **深情專一型** | 不變 |
| 高依附 × 開放 | 深情多元型 | **鍾情博愛型** | 「多元」帶有當代政治意涵，「鍾情博愛」更中性更詩意 |
| 低依附 × 專一 | 探索人性型 | **靈肉分離型** | 「探索人性」太模糊，「靈肉分離」直接點出核心 |
| 低依附 × 開放 | 自由遊戲型 | **遊戲人間型** | 「自由遊戲」太輕，「遊戲人間」更有文學感 |

V3 的命名走更接近古典文學的路數，與 16 天候型的詩意感保持一致。

## 結語

LPAS 從 V1 到 V3 的三個月，是一場「**核心觀察不變、實作架構大幅迭代**」的過程。

不變的部分：
- 愛情是最複雜的情感
- 分成三階段測量
- 為了讓 AI 寫出真實的角色而存在
- 「角色推動劇情」的創作哲學

不斷在變的部分：
- 軸數、軸名、類型數、類型名
- 題庫設計、計分邏輯
- 角色卡格式
- 結果頁呈現

V3 不會是最後一版。但每一版的改變，都是為了更接近那個從一開始就在那裡的核心問題：**怎麼讓 AI 真的理解一個「人」。**
