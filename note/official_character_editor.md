# 🎭 角色資料編輯器 使用手冊（官方）

> 適用版本：V0.9.5.0 之後
> 對應網頁：`web/characters_editor.html`

## 一、這個工具的定位

LPAS 測驗只給角色**人格骨架**。一個能上場的角色還需要姓名、外貌、生日、血型、口吻、生圖 prompt⋯⋯這些「血肉」在此補完。

也支援反向作業：**丟一段文字或一張圖片，AI 反推出完整角色卡**。

---

## 二、頂部工具列

| 按鈕 | 功能 |
|---|---|
| 🔄 | 從雲端重新下載角色卡清單 |
| 🆕 儲存新角色 | 另存為新角色卡（自動生成 ID） |
| 💾 儲存角色（覆蓋） | 覆蓋目前 ID 的雲端資料 |

---

## 三、基本欄位

### 身份

- 姓名、性別、身高、體重、上圍
- 生日、星座、血型、MBTI

### LPAS v3 四型（V3 規格）

- 曖昧期類型（16 天候型之一：海嘯 / 煙火 / 漩渦 / 陣雨 / 岩漿 / 太陽 / 藤蔓 / 燈塔 / 雷雨 / 流星 / 流沙 / 晨露 / 梅雨 / 晚霞 / 深海 / 迷霧）
- 熱戀期類型（同上 16 型）
- 失戀期類型（同上 16 型）
- 親密關係類型（4 型：深情專一 / 鍾情博愛 / 靈肉分離 / 遊戲人間）

右側面板會即時顯示所選型別的完整說明文字。

---

## 四、角色照片（V0.9.5.0 新增）

- 160×160 縮圖框（深灰底、淺灰虛線框）
- **拖曳圖片至縮圖框** 或 **點擊 📁 上傳圖片** 均可
- 系統自動：
  - 縮圖 = 最長邊 256 px
  - 原圖 = 最長邊 1024 px
  - 皆為 JPEG（80% 壓縮）
- 儲存至 Supabase `characters.photo_thumb` 與 `characters.photo_full`
- **🗑️ 清除照片** 清空目前的照片資料

**注意**：Supabase 需先新增這兩個欄位：
```sql
ALTER TABLE characters ADD COLUMN photo_thumb text;
ALTER TABLE characters ADD COLUMN photo_full  text;
```

## 五、角色設定 JSON（Card JSON）

- 完整角色卡的 JSON 內容，所有其他欄位變動時會自動同步
- 可手動微調（例如加入自訂習慣、口頭禪）

### 三個 AI 分析按鈕

| 按鈕 | 功能 |
|---|---|
| 📋 剪貼簿創造角色 | 讀剪貼簿文字 → AI 分析出角色卡 |
| 📝 文字創造角色 | 讀本機文字檔 → AI 分析出角色卡 |
| 🖼️ 人像圖片生成提示詞 | 讀人像圖片 → AI 產出生圖 prompt |

**多角色文字分析**：文字中若有多個角色，會先彈窗要求輸入「單一角色姓名」，讓 AI 聚焦分析。

### 4090 24GB 上下文限制
- 雖然gemma4跟Qwen3.6都支援256k(262144)上下文，但是過多的上下文會耗費大量VRAM導致速度變很慢且亂回答。
- ⭕若使用容量20GB的模型時，上下文勿超過`8192`，否則會明顯變慢。
- ⭕若使用容量17GB的模型時，上下文勿超過`65536`，否則會明顯變慢。
- ⭕若使用容量13GB以下的模型時，上下文勿超過`131072`，否則會明顯變慢。
- ⛔❌🚫別使用20GB以上的模型，根本沒有上下文的空間，立刻就爆記憶體，速度變很慢且會亂回答。

### 使用 qwen3.6:27b，溫度需標準或以下。
- 溫度 0.9(標準)，沒問題。
- 溫度 1.0(微溫)以上，輸出混亂且短。

### 4060顯卡 推薦

### 4060 16GB上下文限制
- 雖然gemma4跟Qwen3.6都支援256k(262144)上下文，但是過多的上下文會耗費大量VRAM導致速度變很慢且亂回答。
- ⁉️一個中文字至少有兩倍容量，7000個字至少需要`14000`的上下文，加上其他系統提示詞至少要`16384`。
- ⁉️簡單來說，若OLLAMA無法輸出文字時，請先加大`num_ctx`上下文容量。
- ⭕若使用容量15GB的模型時，上下文勿超過`8192`，否則會明顯變慢。
- ⭕若使用容量13GB的模型時，上下文勿超過`65536`，否則會明顯變慢。
- ⭕若使用容量10GB以下的模型時，上下文勿超過`131072`，否則會明顯變慢。

**載入雲端／本機資料時，LOG 欄會顯示雲端原始 AI 設定值**，即使該模型已被刪除仍可看到原始字串，方便重新拉模型。

## 八、常見問題

### Q：AI 分析文字失敗？
- 確認 Ollama 有跑起來、模型已下載
- 檢查 LOG 欄的完整錯誤訊息
- 文字檔請以 UTF-8 儲存

### Q：舊 V1 角色卡怎麼辦？
`lpas_v1_to_v3.js` 會在載入時自動就地補上 `lpas_v3` 欄位。若「親密關係類型」為空，儲存時會自動補預設。

### Q：如何刪除角色卡？
目前介面不支援刪除，需到 Supabase Dashboard 手動操作或改 `is_active = false`。

## 九、資料儲存位置

- **雲端**：`characters` 表
- **本機**：`characters/` 目錄下的 JSON（除錯用）
- **關鍵欄位**：`card_json`（完整角色卡）、`lpas`（人格類型代碼）、`photo_thumb`、`photo_full`、`is_active`
